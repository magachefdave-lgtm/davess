# 세부 사용성 보완 구현 계획

**Goal:** v3.18.40 검수 9건을 보완하고 사원 이름은 새 등록 시 최대4자로 제한하여 다시 확인한다.
**Architecture:** 기존 모달 공통 도우미와 실제 저장 API를 재사용한다. 자료 식별자인 기존 사원 이름은 임의로 자르지 않고 보존하며, 새 이름을 추가할 때 UI·서버에서 4자 제한을 검증한다. 메인 카드 위치와 승인·신청·권한 규칙은 유지한다.
**Tech Stack:** Python/FastAPI/SQLite, 기존 JavaScript/CSS, Chromium, GitHub Windows 빌드.
**Spec:** 검수기준_v3.18.40_세부사용성.md 및 사용자 8번 최대4자 조건.

## 계약과 작업 경계
- 공통 모달: 기존 MODAL_CLOSERS의 닫기 가드·콜백을 유지한다. 최상위 창만 Escape/Tab을 처리하고 열기/닫기에 초점을 이동/복귀한다. 비동기 목록 갱신은 모달 재열기로 취급하지 않는다.
- 복구: OnAirUI.registerClose(id, callback)로 복구창을 공통 닫기 순서에 등록한다. 복구 전용 Escape 중복 처리는 제거한다. 내용 갱신 시 안정된 컨트롤/체크 대상과 스크롤을 보존하고 성공하면 이전 오류를 지운다.
- 설정: 성공한 제출 스냅샷만 비교 기준에 반영하고, 저장 중 다시 입력한 값을 기준으로 삼지 않는다. 실패/취소는 입력을 보존한다.
- 검색: 화면에 보이는 신규/변경 전후/취소 기간을 모두 검색한다.
- 이름: 신규 사원4자 상한, 기존 긴 이름은 변경 없이 읽기·저장·복원 가능. 새 사원5자는 저장 전에 거절하고 기존 자료는 유지한다. 입력/암호 취소 시 사원 이름·성별 유지.
- 장기 부재: 한 줄의 이름·기간을 유지하며 기간 폭을 먼저 확보하고 이름을 줄인다.

## Review Focus
1. 닫기 확인·암호·복구 중첩에서 Escape 한 번은 최상단 하나만 처리하고 저장 가드를 보존한다.
2. 목록 갱신·비동기 완료가 다른 화면으로 이동한 사용자의 초점을 빼앗지 않는다.
3. 설정 저장 요청이 실패하거나 저장 대기 중 필드를 고쳐도 비교 기준과 입력값이 어긋나지 않는다.
4. 기존 긴 사원 이름과 일정·신청 연결이 유지되고 잘못된 새 이름 때문에 전체 저장이 부분 반영되지 않는다.
5. 4자 한국어 이름·한글 IME 조합과 붙여넣기, 한 해를 넘는 기간도 현재 칸 안에 읽힌다.
