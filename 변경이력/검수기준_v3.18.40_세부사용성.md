# WLR OnAir v3.18.40 전체 사용성 세부 검수

2026-11-17 KST · 관리자와 조회용 · 기준 커밋 dc51d7e593a9b54aeed8f6085bd9d5ba9e4e7992

당직·휴가·교육·부재·회식 날짜 취합을 운영하는 부서용 프로그램입니다. 한 부서에서 여러 직원이 각 PC로 같은 자료를 쓰는 사용을 기준으로 검수했습니다. 사원 12명, 다수 신청·휴가·공휴일·PC 연결, 긴 이름과 긴 사유를 합성 자료로 구성했습니다.

1920×1080, 1366×768, 1024×768 Chromium에서 실제 Admin/Viewer 프로필과 격리된 SQLite 서버로 확인했습니다. 헤더 최신 버전 상태는 다섯 가지 API 시험 응답으로 표시를 점검했습니다. 제품 소스와 배포 버전은 변경하지 않았습니다.

## 먼저 수정할 문제

### 1. 같은 창에서 연결 설정을 되돌려 저장해도 실제 파일에는 변경된 값이 남음 — P2

연결 정보 → 자주 바꾸는 설정에서 포트를 원래 값 50883에서 18234로 저장한 뒤, 같은 창에서 50883으로 되돌리고 저장했습니다. 화면은 '바뀐 값이 없습니다'라고 표시하고, 실제 임시 설정 파일에는 18234가 남았습니다. 다음 실행 때 예상과 다른 포트로 열릴 수 있습니다.

저장 성공 후 비교 기준인 d.settings가 갱신되지 않는 원인입니다. 성공한 제출값을 기준값에 반영해야 합니다. 저장 대기 중 사용자가 다시 입력한 값으로 기준을 잡아서는 안 됩니다. 수정 후 'A → B 저장 → A 저장', 실패 후 재시도를 함께 검증해야 합니다.

- 소스: frontend/dist/update_status.js:374–385
- 근거: core/settings-evidence.json, core/settings-revert-not-saved.png

### 2. 창을 열어도 키보드가 뒤의 본화면 버튼을 작동시킴 — P2

근무 규칙 설정을 클릭하고 Tab 한 번, Enter를 누르면 뒤에 가려진 자동 배정이 실행됩니다. 근무 규칙 창이 열린 상태로 자동 배정 범위 창까지 열립니다. 두 주요 해상도에서 재현했습니다. 사원 명단·당직 통계·변경 이력·명절 근무표·연결 정보·내 신청 내역에서도 창으로 초점이 진입하지 않거나 Tab이 배경으로 빠집니다.

기존 모달의 공통 열기/닫기 처리에서 최초 초점, 최상위 창 내부의 Tab·Shift+Tab 순환, 배경의 키보드 접근 차단과 닫은 뒤 호출 버튼 복귀를 맞춰야 합니다. 레이아웃 변경은 필요하지 않습니다. 모달마다 임시 키 처리를 추가하기보다 하나의 공통 순서로 처리하는 편이 안전합니다.

- 소스: frontend/dist/index.html:8034, 8201–8219, 8287, 10194; frontend/dist/usability_admin.js:177; frontend/dist/usability_requests.js:530–541
- 근거: modal/followup-evidence.json, modal/rule-background-assignment-1366.png, viewer/history-background-focus.png

### 3. 승인 목록 검색에서 보이는 종료일·변경 전 날짜를 찾지 못함 — P2

여러 날의 신규 신청, 일정 변경, 취소 요청에서 화면에 표시된 종료일을 검색하면 0건으로 나옵니다. 일정 변경의 변경 전 시작일·종료일도 찾지 못하고, 변경 후 시작일 검색은 해당 행을 찾았습니다.

검색 문자열이 시작일 등 일부 필드만 포함합니다. 화면에 표시하는 원본 기간·변경 기간·취소 기간의 시작일과 종료일을 같은 검색 자료에 포함해야 합니다. 날짜 표기 형식도 검색 안내와 맞춰야 합니다.

- 소스: frontend/dist/usability_requests.js:584
- 근거: approval-ca의 15/16 검색 캡처와 검색 결과 JSON

### 4. 신청 권한 복구에서 Escape 한 번에 뒤의 내 신청 내역까지 닫힘 — P2

내 신청 내역 → 신청 권한 복구 → Escape를 누르면 복구창과 뒤의 내 신청 내역창이 함께 닫힙니다. 사용자는 이전 목록으로 돌아갈 수 없습니다.

복구창이 공통 MODAL_CLOSERS에 등록되지 않은 채 별도의 document Escape 처리기를 사용하여 두 처리기가 모두 실행됩니다. 복구창을 공통 최상위 창 순서에 포함하고 기존의 중복 처리를 정리해야 합니다. Escape 한 번에는 한 창만 닫혀야 합니다.

- 소스: frontend/dist/request_access.js:107; frontend/dist/index.html:10194–10205
- 근거: viewer/recovery-before-escape.png, viewer/recovery-after-escape.png

### 5. 권한 복구창에서 새로고침·선택 시 키보드 초점과 스크롤이 초기화됨 — P2

직원 복구창의 다시 확인을 누르면 초점이 BODY로 빠집니다. 같은 처리를 자동 새로고침에서도 사용합니다. 관리자 복구 대상 목록에서 Space로 체크하면 체크한 항목은 유지되지만 초점이 BODY로 이동하고, 아래쪽에서 선택하면 스크롤이 1800에서 0으로 돌아옵니다. 긴 목록을 연속 선택하기 불편합니다.

성공할 때마다 내용 전체를 innerHTML로 교체하는 원인입니다. 갱신 전 활성 컨트롤의 안정된 식별자와 목록 스크롤을 보존하고 갱신 후 복원하거나, 바뀐 내용만 갱신해야 합니다. 선택값 보존과 승인 검증은 유지해야 합니다.

- 소스: frontend/dist/request_access.js:57, 101, 105
- 근거: viewer/recovery-refresh-focus-lost.png, approval-ca/recovery/evidence.json 및 04-scroll-reset-after-selection.png

## 함께 다듬을 문제

### 6. 사원 추가 중 암호를 취소하면 입력한 이름이 사라짐 — P3

암호 보호 상태에서 이름을 입력해 추가하고 암호창을 취소하면 입력 이름이 빈칸이 됩니다. DB와 명단에는 추가되지 않아 자료 오류는 없지만, 다시 입력해야 합니다.

저장 결과를 받기 전에 입력란을 비우기 때문입니다. 성공한 경우에만 비우고 취소·실패 시 입력 이름·성별과 초점을 유지해야 합니다.

- 소스: frontend/dist/index.html:8061–8066
- 근거: modal/member-password-cancel-lost-draft.png, modal/evidence.json

### 7. 복구창 연결이 회복돼도 이전 오류가 계속 표시됨 — P3

복구 목록 조회에 503 시험 응답을 준 뒤 정상 응답으로 재시도하면 본문은 정상으로 갱신되지만 아래 ra-error의 이전 실패 문구가 남습니다. 현재도 실패 중인 것으로 오해할 수 있습니다.

오류 표시 함수는 문구를 넣지만 직원 복구 목록의 성공 경로는 이를 지우지 않습니다. 성공 시 해당 오류를 비우고, 최신 요청 결과가 이전 요청의 화면을 덮지 않도록 처리해야 합니다.

- 소스: frontend/dist/request_access.js:52, 57
- 근거: viewer/recovery-stale-error.png, viewer/workflow-results.json

### 8. 긴 사원 이름이 금일 당직자 칸을 넘어 옆 칸과 겹침 — P3

등록 가능한 이름 '김민수테스트긴이름'을 금일 당직자로 넣으면 이름이 칸을 넘어 금일 휴가·부재 영역과 겹칩니다. 1920·1366·1024 폭에서 재현했고, 휴가자가 한 명인 상태에서도 확인했습니다. 보통 길이의 이름은 정상입니다.

그리드 항목이 내용의 최소 폭보다 작아지지 않아 이름의 말줄임이 작동하지 않습니다. 항목에 min-width:0을 적용하고 이름 폭을 칸 안으로 제한해야 합니다. 기존 전체 이름 title과 클릭 상세를 보존하면 됩니다.

- 소스: frontend/dist/index.html:2165–2176, 2204
- 근거: layout/1366x768-single-verified.png

### 9. 장기 부재·파견의 긴 이름 옆 기간에서 끝 요일이 잘림 — P3

관리자 휴가·부재 관리의 달력 아래 장기 목록에서 긴 이름과 연도를 넘는 기간을 한 줄에 표시하면, 목록 폭 218px에 227px 내용이 들어가 끝 요일이 잘립니다. 전체 내용은 title로 확인할 수 있어 표시 문제로 분류했습니다. 일반적인 이름은 정상입니다.

이름과 기간이 모두 flex:none이라 둘 다 줄어들지 않는 원인입니다. 기간을 읽을 수 있는 폭을 먼저 확보하고 이름만 말줄임하도록 조정하는 것이 권장됩니다. 현재의 한 줄 형식과 전체 내용 확인 수단을 유지할 수 있습니다.

- 소스: frontend/dist/absence_management.css:85–87
- 근거: layout/1920x1080-absence.png와 layout/results.json

## 수정 순서와 검증 범위

1. 설정 저장의 기준값을 바로잡고, 각 모달의 공통 키보드/닫기 순서를 맞춥니다(1·2·4).
2. 복구창의 갱신·오류 처리와 승인 날짜 검색을 보완합니다(3·5·7).
3. 사원 입력 유지와 긴 이름의 표시 범위를 조정합니다(6·8·9).

독립 검수자가 소스와 재현 근거를 다시 대조했습니다. 초기 합성 빈 DB 백업의 미리보기 오류와 연결 정보의 정상적인 2단계 Escape는 오탐으로 제외했습니다. CA 연도 선택 후 닫기 버튼으로 초점 이동, 검색 결과 없는 대상 목록의 빈 공간은 낮은 우선순위 관찰로 남겼으며 위 확정 결함 수에 포함하지 않았습니다.

Windows EXE GUI·트레이·DPAPI·운영 공유폴더·실제 PC의 확대 배율·화면 읽기 프로그램 음성 출력은 이번 검수에 포함하지 않았습니다. 자동 배정 최종 적용·실제 백업 복원은 이번 사용성 검수에서 실행하지 않았습니다. 브라우저 검수 결과가 모든 환경의 무결함을 보장하는 것은 아닙니다. 현재 배포 파일은 v3.18.40이며, 이 보고서는 수정 전 검수 결과입니다.
