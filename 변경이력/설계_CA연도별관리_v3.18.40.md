# CA 연도별 관리 구현 계획

**목표:** 올해·내년 CA를 함께 지정하고 담당자·임기·PC 승인 상태를 넓은 화면에서 구분한다.
**구조:** 기존 임명과 연결은 보존하고 추가 임명을 별도 저장한다. 임명별 revision과 PC 연결을 분리하며 한국 날짜의 임기 시작/종료로 권한을 판단한다.
**기술:** 기존 Python·SQLite·JavaScript·CSS 및 GitHub Windows 빌드 재사용.
**요구:** 올해·내년 담당자 지정, 선택 담당자의 상태와 연결 승인 구분, 최대화 화면에서 스크롤 최소화. 기존 메인 구성은 유지한다.

## 공동 계약
- 역할은 기존 필드와 numeric roleId를 가진다. 기존 단일 임명은 1, 새 연도 임명은 해당 연도 숫자를 사용한다.
- manage와 summary에 roles 배열, summary에 선택 이름의 assignedRole을 추가한다. role은 현재 담당자 호환 필드다.
- 임명 저장과 연결 요청에 roleId를 전달한다. 임명 revision·연결 승인은 해당 임명에만 적용한다.
- 미래 CA의 PC는 미리 승인할 수 있지만 임기 시작 전에는 회식 관리 권한이 없다.
- 임기는 겹칠 수 없다. 기존 2년 임명은 전체 기간을 그대로 표시하고 임의로 잘라내지 않는다.
- 올해·내년 카드를 선택하면 편집 영역과 연결 목록이 같은 담당자를 보여 준다. 대기/승인/미요청/임기 대기를 구분한다.
- 많은 연결은 페이지로 나누고 1920×1080, 1366×768에서 모달 높이를 확인한다. 작은 화면은 내용을 숨기지 않고 세로 스크롤을 허용한다.

## 검수 초점
내년 임명 시 올해 PC 무효화, 같은 직원의 연속 임기 연결 혼동, 자정 임기 전환과 겹친 날짜, 만료/삭제/복원된 권한 부활, 오래된 편집 화면의 덮어쓰기, 목록이 길 때 버튼·이름 잘림을 확인한다.

## 추가 요청
관리자 암호가 설정된 PC에서 새 부재 등록 시 암호창이 뒤로 가려지는 문제를 재현하고, 암호창·당직 공백 안내창의 표시/닫기 순서를 공통 모달 순서와 맞췄다. 취소·오입력·저장·복귀를 실제 브라우저로 검증했다.
