WLR OnAir 시작하기 (운영 담당자용, 처음부터 끝까지)
==========================================================

이 폴더는 프로그램을 "만드는(빌드)" 소스입니다. 실행 파일(exe)은 아직 없습니다.
아래 순서대로 한 번만 따라 하면 됩니다. 각 단계 옆의 시간은 대략적인 값입니다.

[전체 흐름]
  인터넷 PC: 1 Python 설치 → 2 부품(wheels) 모으기
  사내 빌드 PC: 1 Python 설치 → 3 폴더 복사 → 4 빌드 → 5 첫 게시 + 키 백업
  각 PC: 6 설치 ZIP 나눠 주기 → 7 첫 실행 설정
  이후: 8 새 버전 올리기 / 9 되돌리기 / 10 문제가 생기면


1. Python 설치 (인터넷 PC와 사내 빌드 PC 둘 다, 약 5분)
------------------------------------------------------------
  - 인터넷 PC에서 https://www.python.org/downloads/windows/ 를 엽니다.
  - "Windows installer (64-bit)" 3.11~3.14 중 하나를 내려받습니다.
    (예: python-3.13.x-amd64.exe). 3.15 이상, 32-bit, ARM64, "free-threaded" 는 안 됩니다.
  - 사내 빌드 PC가 인터넷이 안 되면, 이 설치 파일(.exe)을 USB 등으로 함께 가져갑니다.
  - 설치 화면 맨 아래 "Add python.exe to PATH" 에 체크하고 "Install Now" 를 누릅니다.
    (py launcher 항목도 켜져 있으면 빌드 파일이 Python 을 자동으로 찾습니다.)
  - Microsoft Store 의 Python 은 쓰지 않습니다.


2. 부품(wheels) 모으기 - 인터넷 PC에서 (약 3~5분)
------------------------------------------------------------
  - 이 소스 폴더 전체를 인터넷 PC의 로컬 폴더(예: C:\OnAir_Build)에 풉니다.
  - collect_wheels.cmd 를 더블클릭합니다. 끝나면 wheels 폴더가 생깁니다.
  - 실패하면 화면에 나온 로그 파일(build_logs\collect_wheels_날짜.log)을
    IT 담당자나 도와주는 사람에게 보내 주세요.
  - 빌드 PC가 인터넷이 된다면 이 단계는 건너뛰어도 됩니다.


3. 사내 빌드 PC로 복사 (몇 분)
------------------------------------------------------------
  - wheels 폴더를 포함한 소스 폴더 전체를 사내 빌드 PC의 로컬 디스크로 복사합니다.
    (예: C:\OnAir_Build). 네트워크 공유 폴더에서 바로 빌드하지 마세요.


4. 빌드 - 사내 빌드 PC에서 (약 10~20분)
------------------------------------------------------------
  - build_windows.cmd 를 더블클릭합니다. 창에 "[1/5] 빌드 준비 확인" 같은 단계와
    2/5는 짧은 임시 폴더에서 준비합니다. 기존 화면·업무 기능은 유지됩니다.
    실패하면 2-a/2-b 구분과 마지막 오류가 창에 표시됩니다.
    예상 시간이 나옵니다. 가장 오래 걸리는 단계는 4/5 입니다. 창을 닫지 마세요.
  - 3.18.23부터 3/5는 정상 패키지를 저장해 재사용합니다. 처음에는 필요한 파일을 받지만,
    같은 Python 계열·패키지 목록으로 다시 빌드할 때는 저장된 파일을 사용합니다.
    저장 위치: %LOCALAPPDATA%\WLR_OnAir\build-wheels (직접 경로를 지정할 필요 없음)
    wheels 폴더가 있으면 기존처럼 그 폴더를 먼저 사용합니다.
  - 성공하면 완료 폴더(dist\source-build-날짜...)가 탐색기로 열립니다.
  - 실패하면 화면에 나온 로그 파일(build_logs\날짜.log) 하나와 창 화면 캡처를 보내 주세요.


5. 첫 게시 + 서명 키 백업 (약 5분)  ※ 키 백업을 꼭 하세요
------------------------------------------------------------
  - 4단계에서 열린 완료 폴더 안의 배포관리.cmd 를 더블클릭합니다.
    (소스 폴더 맨 위의 배포관리.cmd 를 누르면 완료 폴더를 대신 열어 줍니다.)
  - 브라우저에 "업데이트 배포 관리" 화면이 열립니다.
    1) 공유 PC의 업데이트 폴더: 직원 PC들이 읽을 수 있는 공유 폴더(예: \\공유PC\WLR_Update)
       처음이면 빈 폴더를 고르고, 나타나는 "이 폴더에 새 업데이트 저장소를 만드는 것이 맞습니다."에
       체크합니다. (이미 게시한 적 있는 폴더에는 이 체크 칸이 나오지 않습니다)
    2) Update ZIP 칸은 자동으로 채워져 있습니다.
    3) 직원 PC용 설치 ZIP 폴더는 완료 폴더 안의 직원PC_설치ZIP 폴더가 기본값입니다.
    4) [게시] → 확인 창의 폴더·대상을 확인하고 [확인]. 진행 단계가 화면에 나옵니다(2~5분).
  - 첫 게시에서는 이 PC에 "서명 키"가 자동으로 만들어지고, 게시 직후 노란 상자
    "지금 서명 키 백업을 만드세요"가 나옵니다.
    - 백업 암호(12자 이상)를 두 번 입력하고 [키 백업 만들기]를 누릅니다.
    - 만들어진 백업 파일을 USB 등 이 PC 밖에도 한 부 복사하고, 암호는 따로 적어 둡니다.
    - 키를 잃으면 모든 PC에 설치 ZIP을 다시 배포해야 합니다.
  - 화면에 나온 "업데이트 서명 공개 키 지문"을 [복사]해 두었다가 직원에게 따로 알려 줍니다.
  - 이 창은 15분 동안 열려 있습니다. "창이 닫혔습니다"가 나오면 배포관리.cmd 를 다시 실행하세요.


6. 설치 ZIP 나눠 주기
------------------------------------------------------------
  - 게시가 끝나면 설치 ZIP 폴더(완료 폴더 안의 직원PC_설치ZIP)가 탐색기로 열립니다.
    WLR_OnAir_버전_Admin.zip  : 관리자 PC용
    WLR_OnAir_버전_Viewer.zip : 직원(조회용) PC용
  - 설치 ZIP은 "처음 설치하는 PC"에만 한 번 전달합니다. 이후 새 버전은 자동으로 받습니다.


7. 각 PC 첫 실행 설정 (PC당 약 2분)
------------------------------------------------------------
  - 설치 ZIP을 로컬 폴더(예: C:\WLR_OnAir\조회용)에 모두 풉니다.
  - WLR_OnAir_Viewer.exe(또는 Admin.exe)를 더블클릭하면 첫 설정 화면이 열립니다.
    - 화면 맨 위의 지문이 5단계에서 알려 준 지문과 같은지 [복사]해서 비교합니다.
    - "기존 공유 폴더 사용": 그 PC에서 예전 WLR OnAir 를 쓰던 경우. 예전 프로그램 폴더를 [찾아보기]로 고르고,
      예전 프로그램을 트레이에서 종료한 뒤 체크합니다.
    - "이 PC를 새로 연결": 처음 쓰는 PC. 공유 데이터 폴더(smart_duty.db 가 있는 폴더)를 고릅니다.
    - "새 데이터 만들기": 관리자용에서, 처음 도입할 때만.
  - [저장하고 시작]을 누르면 프로그램이 뜹니다.


8. 새 버전 올리기 (소스를 고쳤거나 새 소스를 받았을 때)
------------------------------------------------------------
  - 소스 폴더의 버전올리기.cmd 를 더블클릭 → 새 버전 번호 입력(그냥 Enter = 마지막 숫자 +1).
    버전 파일 3곳과 SOURCE_MANIFEST.json, SHA256SUMS.txt 가 한 번에 맞춰집니다.
    (새로 받은 소스 ZIP 의 버전이 이미 올라가 있으면 이 단계는 필요 없습니다.)
  - 4단계(빌드) → 5단계(배포관리.cmd 로 게시)를 다시 합니다. 키 백업은 이미 했다면 생략됩니다.
  - 직원 PC는 프로그램을 다시 시작할 때 새 버전을 받습니다.
  - 빌드나 확인 중 "버전 번호가 서로 다릅니다"가 나오면 버전올리기.cmd 를 실행하세요.


9. 되돌리기 (새 버전에 문제가 있을 때)
------------------------------------------------------------
  - 급하면 먼저 배포관리.cmd → "4. 비상 정지 / 저장소 복원" 칸을 펼치고
    "일시 정지·해제할 대상"(조회용만 / 관리자용만 / 관리자용 + 조회용)을 고른 뒤
    [선택한 대상의 업데이트 일시 정지] → 확인 창에서 [확인].
    직원 PC들은 지금 설치된 버전으로 계속 실행합니다.
  - 예전 버전으로 되돌리려면: 예전 소스 ZIP을 새 폴더에 풀고 → 버전올리기.cmd 로
    "지금 게시된 버전보다 높은 번호"를 입력 → 빌드 → 게시 →
    [선택한 대상의 일시 정지 해제].
    (게시는 항상 더 높은 번호만 받습니다. 낮은 번호로는 되돌릴 수 없습니다.)
  - 직원 PC에서 새 버전이 시작되지 않으면 그 PC는 자동으로 이전 버전으로 실행하고,
    화면 위에 안내가 한 번 나옵니다. 문제가 해결되면 그 PC의 [연결 정보] →
    "차단된 업데이트 다시 허용"을 누르고 프로그램을 다시 시작합니다.


10. 로그와 상태는 어디에 있나
------------------------------------------------------------
  - 빌드 기록: 소스 폴더\build_logs\날짜.log  (wheels 모으기: collect_wheels_날짜.log)
  - 각 PC 프로그램 기록: 프로그램 화면 [연결 정보] → 업데이트 상태 → [로그 폴더 열기]
    (위치: %LOCALAPPDATA%\WLR_OnAir\ADMIN 또는 VIEWER 폴더의 launcher.log, application.log)
  - 마지막 업데이트 결과(성공/실패, 받은 버전)도 [연결 정보]에 나옵니다.
  - 설정(관리자 암호, 포트, 접속 이름, 추가 백업 폴더)은 [연결 정보] → "자주 바꾸는 설정 (이 PC)"에서
    바꾸고 [설정 저장]을 누릅니다. 원래 파일은 사본(.bak)으로 남습니다.
    바꾼 뒤에는 프로그램을 다시 시작해야 적용됩니다.
    그 밖의 항목은 [설정 파일 열기 (메모장)]로 메모장에서 고칩니다.
  - 도움을 요청할 때는 해당 로그 파일과 화면 캡처를 함께 보내 주세요.
    로그에는 서명 키나 백업 암호가 들어 있지 않습니다.
